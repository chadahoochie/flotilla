# Protocol Architecture & Datagram Framing Overview

## Framing Principles
Flotilla uses UDP datagrams framed to fit comfortably within Ethernet MTU boundaries (maximum transmission unit of 1500 bytes, resulting in a maximum payload of 1472 bytes over IPv4 UDP).

## Wire Format Architecture
Every datagram transmitted across cluster nodes begins with a fixed 40-byte [`PacketHeader`](file:///home/chad/source/rust/flotilla/src/codec/packet_header.rs):

```
+-------------------------------------------------------------+
| Magic (4 bytes) | Version (2 bytes) | Message Type (2 bytes) |
+-------------------------------------------------------------+
| Sender ID (8 bytes)             | Receiver ID (8 bytes)     |
+-------------------------------------------------------------+
| Term (8 bytes)                                              |
+-------------------------------------------------------------+
| Checksum CRC32 (4 bytes)       | Payload Length (4 bytes)   |
+-------------------------------------------------------------+
| Variable Payload (Log entries, vote responses, etc.)        |
+-------------------------------------------------------------+
```

## Zero-Copy Deserialization
Leveraging `zerocopy 0.8`, the byte slice `&[u8]` received from a UDP socket is directly viewed as a `&PacketHeader` without allocations or buffer copies.
Payload validation is performed via IEEE 802.3 CRC-32 (`crc32fast`).
