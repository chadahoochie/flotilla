# Archive Subsystem Overview

## Archiving Architecture
The consensus core operates at microsecond latencies in DRAM. In order to store historical state durably and avoid running out of pre-allocated ring buffer slots, committed log entries are transferred across a bounded pipeline to an asynchronous background worker.

## Components
1. [`ArchivePipeline`](file:///home/chad/source/rust/flotilla/src/archive/archive_pipeline.rs): Manages the buffered queue of committed [`ArchivedEntry`](file:///home/chad/source/rust/flotilla/src/archive/archived_entry.rs) items between the Raft state machine and the background worker, bounded by [`PipelineError`](file:///home/chad/source/rust/flotilla/src/archive/pipeline_error.rs).
2. [`AsyncArchiveSink`](file:///home/chad/source/rust/flotilla/src/archive/async_archive_sink.rs): Trait implemented by durable storage targets (`write_entries`, `flush`).
3. Persistent Sinks:
   - [`FileArchiveSink`](file:///home/chad/source/rust/flotilla/src/archive/file_archive_sink.rs): Append-only WAL file sink with record checksums.
   - [`NullArchiveSink`](file:///home/chad/source/rust/flotilla/src/archive/null_archive_sink.rs): Fast in-memory sink for testing and benchmarking.
4. Watermark Advancement: Monotonically advancing index acknowledging durable persistence, allowing the consensus core to compact and advance `first_index`.
