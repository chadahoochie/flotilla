# Consensus Subsystem Overview

## Sans-I/O Architecture
The consensus state machine in Flotilla is completely decoupled from OS timing primitives and network sockets. It provides two primary input methods:
1. `step(event)`: Process an inbound RPC packet envelope or client proposal.
2. `tick()`: Advance the internal logical clock tick for election timeouts and heartbeat cadence.

Both methods yield an iterator or slice of outbound actions (e.g. `SendMessage`, `ApplyCommitted`, `PersistHardState`) without blocking or making syscalls.

## Modular Public Decomposition
To adhere to the strict design rule of having **no private helper methods**, the consensus engine is split across dedicated public modules:
- `election`: Pure election logic, timeout counters, vote request evaluation.
- `replication`: Peer progression tracking, match/next index book-keeping, AppendEntries creation.
- `commit`: Quorum calculation and commit index advancement.
- `engine`: The top-level composition type `RaftNode`.
